步驟

  
    
    
  1. 命令列熱身。

-- 檔案：mycoarea.pmlfnc
define function !!mycoArea(!Length is REAL, !Width is REAL) is REAL
    !result = !Length * !Width
    return !result
endfunction

  
    
    
  1. 重建索引。
    在命令列執行 pml rehash all。沒有這一步，系統不會知道新檔案存在。
    2. 
    
  2. 呼叫並檢查。
    輸入 !a = !!mycoArea(7, 6)，再輸入 q var !a。應該看到 REAL 42。
    3. 
    
  3. 故意犯錯。
    輸入 !!mycoArea('7', 6)，記下錯誤訊息與錯誤碼。這是後面寫 handle 的材料。

q var !a              →  REAL  42

常見錯誤

  

  
症狀原因處理

  
  
找不到 MYCOAREA沒 rehash，或檔案不在 PMLLIB 底下確認路徑後執行 pml rehash all

  
改了內容卻沒生效系統用的是快取版本再 pml rehash all；必要時 pml reload object

  
函式被當成未定義檔名與函式名不一致（含大小寫或拼字）檔名 = 函式名，通常全小寫

  
計算結果不是預期傳入的是字串，或引數順序顛倒用 q var 檢查型別；需要時先 .real()

  • 能說出 .pmlfnc 的檔名規則
    •

LAB 02陣列、間隙與計數約 20 分鐘


  

    
前置條件
    
      
  • 完成 LAB 01，能在命令列自在輸入
    • 
      
  • 知道 q var 會顯示型別與值
    • 
    

    
你會得到
    
      
  • 一個含間隙的陣列，以及可預期的走訪結果
    • 
      
  • 「有效元素數」為什麼要自己數
    • 
      
  • 索引 0 與負索引的實際行為
    • 
    

  


  
步驟

  
    
    
  1. 建立空陣列。
    !tags = ARRAY()，再用 q var !tags 看它長什麼樣。
    2. 
    
  2. 故意跳號。
    只設索引 1、2、4，跳過 3。這是最常見的真實情況：刪資料後留下的洞。
    3. 
    
  3. 先看洞。
    q var !tags[3]。它不會是空字串，也不是 0。
    4. 
    
  4. 用索引迴圈走訪。
    不要用最大值猜數量；每一格都檢查是否 UNSET，再決定算不算一筆。
    5. 
  


!tags = ARRAY()
!tags[1] = 'HULL'
!tags[2] = 'OUTFITTING'
!tags[4] = 'DRAWING'

!count = 0
do !i from 1 to 4
    if (!tags[!i].unset()) then
        $P '[' & !i & '] (gap)'
    else
        !count = !count + 1
        $P '[' & !i & '] ' & !tags[!i]
    endif
enddo
$P 'Valid elements: ' & !count

q var !tags[3]

  
    
    
  1. 換一種走訪方式。
    再用 do !t values !tags 走一次，比較輸出順序與筆數。
    2. 
    
  2. 測試邊界。
    試 q var !tags[0] 與 q var !tags[-1]，把結果分別記下來。
    3. 
  


-- 比較用：values 形式
do !t values !tags
    $P 'value: ' & !t
enddo


  
預期結果


[1] HULL
[2] OUTFITTING
[3] (gap)
[4] DRAWING
Valid elements: 3
（q var !tags[3]）UNSET

  
索引 0 可用但多數陣列功能會忽略；負索引已不允許〔待核對：依公司版本確認〕。稀疏陣列用 values 走訪時，間隙是否被跳過依版本而異，要精確控制請用索引迴圈。

  


  
常見錯誤

  

  
症狀原因處理

  
  
少印一筆或多印空白用索引最大值或 .size() 當有效筆數邊走訪邊累加，或用 .unset() 過濾

  
第一格讀不到沿用其他語言的 [0]PML 從 1 起算

  
迴圈只跑一次do 沒寫 enddo，或條件寫在錯的位置檢查 do / enddo 成對

  
中間格變成 UNSET 後才發現刪除元素留下間隙需要連續資料時，寫入時就重建陣列

  
  

  


  
驗收清單

  
    
    
  • 輸出順序與上方預期完全一致
    • 
    
  • 能解釋為什麼計數是 3 而不是 4
    • 
    
  • 能說出 UNSET 與空字串的差別
    • 
    
  • 筆記裡有索引 0 與負索引的實測結果
    •

    4. 
  


-- 檔案：mycocsv.pmlfnc
define function !!mycoCsvCell(!value is STRING) is STRING
    !v = !value.replace('"', '""')
    return '"' & !v & '"'
endfunction

define function !!mycoExportValves(!path is STRING) is REAL
    var !items collect all VALV for CE

    !f = object FILE(!path)
    !f.open('WRITE')
    handle (160,9)
        $P 'Cannot open: ' & !path
        return -1
    endhandle

    !f.writeRecord('SEQ,NAME,TYPE')

    !n = 0
    do !v values !items
        !n = !n + 1
        !f.writeRecord(!n.string() & ',' & !!mycoCsvCell(!v.dbref().name) & ',' & !!mycoCsvCell(!v.type))
    enddo

    !f.close()
    $P 'Rows: ' & !n & ' -> ' & !path
    return !n
endfunction

  
    
    
  1. 重建索引。
    pml rehash all，然後在命令列呼叫。
    2. 
    
  2. 執行匯出。
    先選好 BRANCH，再呼叫函式。回傳值是筆數，負數代表失敗。
    3. 
  


-- 命令列：選好 BRANCH 後執行
!rows = !!mycoExportValves('C:/temp/valves.csv')
handle ANY
    $P 'Export failed: ' & !!error.text
endhandle
q var !rows

  
    
    
  1. 檢查檔案。
    用記事本看原始內容，再用 Excel 開啟。兩邊都要確認欄位沒有錯位。
    2. 
    
  2. 測試失敗路徑。
    把路徑改成不存在的資料夾，確認 handle 有作用、巨集沒有中斷。
    3. 
    
  3. 測試特殊字元。
    找一個名稱含逗號或引號的元素（沒有的話可暫時在測試元素上加），確認匯出後欄位仍正確。
    4. 
  


  
預期結果


SEQ,NAME,TYPE
1,"V-001","VALV"
2,"V-002","VALV"
Rows: 2 -> C:/temp/valves.csv
（q var !rows）REAL  2

  
若 Excel 打開是亂碼，先確認公司編碼約定；必要時改用「資料 → 從文字檔」指定編碼。編碼相關環境變數〔待核對〕。

  


  
常見錯誤

  

  
症狀原因處理

  
  
檔案被打開但沒有內容忘記 .close()，緩衝沒落盤每個成功路徑都要關檔

  
Excel 說檔案被鎖定檔案還開在 Excel 裡關閉 Excel 再匯出

驗收清單

    •

    •

    •

步驟

  
    
    
  1. 先規劃介面。
    兩個唯讀資訊欄（目前元素、輸出路徑）、兩顆按鈕（讀取 CE、匯出 CSV）。先不要加第三顆，介面越小越容易除錯。

-- 檔案：mycovalve.pmlfrm
setup form !!mycovalve size 52 12
    title '閥門清單匯出'
    text .txtInfo '目前元素:' at x1 y1 width 46 is STRING
    text .txtPath '輸出檔案:' at x1 y3 width 46 is STRING
    button .btnPick   '讀取 CE' at x1 y5  width 14 callback '!this.pick()'
    button .btnExport '匯出 CSV' at x17 y5 width 14 callback '!this.export()'
exit

define method .pick()
    !this.txtInfo.val = !!ce.dbref().name
    !this.txtPath.val = 'C:/temp/valves.csv'
endmethod

define method .export()

  1. 先想失敗長什麼樣。
    CE 無效、收集失敗、零筆資料，這三種要分別有訊息。不要用一個大 handle 全部吞掉。
    2. 
    
  2. 每個風險步驟各自接 handle。

    3. 
    
  3. 寫批次函式。

-- 檔案：mycobatch.pmlfnc
-- v1.0  2026-11-02  myco  初版
define function !!mycoBatchRun(!label is STRING) is BOOLEAN
    !name = !!ce.dbref().name
    handle ANY
        $P 'FAILED: no valid CE'
        return FALSE
    endhandle
    $P 'Start: ' & !label & ' / ' & !name

    var !items collect all BRAN for CE
    handle ANY
        $P 'FAILED at COLLECT: ' & !!error.text
        return FALSE
    endhandle

    !n = 0
    do !item values !items
        !n = !n + 1
        $P '  [' & !n & '] ' & !item.dbref().name
    enddo

    if (!n eq 0) then
        $P 'WARN: no BRAN under ' & !name
    endif
    $P 'Done: ' & !n
    return TRUE
endfunction

  
    
    
  1. 開啟追蹤。
    pml trace on（或 $R100），再執行函式。觀察每一行執行的順序與呼叫堆疊。
    2. 
    
  2. 找出慢或錯的行。
    資料量大時，追蹤輸出會很嚇人；先看最後失敗前的幾行，再往前找第一個異常。
    3. 
    
  3. 關閉追蹤。
    pml trace off（或 $R0）。追蹤留在正式環境會拖慢速度並塞爆日誌。
    4. 
    
  4. 測試失敗路徑。
    故意把 CE 移到沒有 BRAN 的層級，確認出現 WARN；再想辦法讓收集失敗，確認回傳 FALSE。
    5. 
    
  5. 寫交接資訊。
    在檔案開頭保留版本、日期、作者、變更摘要；另外記下安裝路徑、環境變更與回滾步驟。
    6.

define function !!mycoBatchRun(!label is STRING) is BOOLEAN
    !name = !!ce.dbref().name
