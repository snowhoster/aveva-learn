官方規則：索引由 1 起算；可跳號（稀疏陣列）；索引 0 可用但多數陣列功能會忽略；負索引已不允許；未設定的元素是 UNDEFINED，不是空字串。

  


  

    
動畫圖解 2　一次資料庫寫入的五個檢查點

    

      
1. 定位確認 !!CE 與 DBREF 真的是目標，不是同名元素。

      
2. 權限確認 MDB 可寫、元素未被他人 claim。

      
3. Claim必要時先 claim，縮小衝突範圍。

      
4. 修改先預覽、再寫入；一次只改一類屬性。

      
5. 驗證savework 後重新查詢，確認值與單位正確。

    

  


  

    
動畫圖解 3　表單事件流

    

      
使用者點擊Button 觸發 callback

      
Callback'!this.pick()' 指定方法

      
Method讀取 !!CE 或查詢資料

      
更新 Gadget把結果寫回表單欄位

      
等待下一次表單保持開啟，不結束巨集

    

  


  

    
動畫圖解 4　PML.NET 的來回

    

      
PML 端表單或巨集發起呼叫

      
橋接層PML.NET 轉型別、傳參數

      
.NET 端C# 處理報表、檔案或 API

      
回到 PML接傳回值，更新介面或訊息

可直接抄用的範例
皆為示意，先在訓練專案執行



  

    
1. 批次列出目前元素的直屬成員唯讀


-- 示意：列出 !!CE 的直屬成員名稱與型別
!ce = !!ce
$P 'Element: ' & !ce.dbref().name

do !member values !ce.members()
    $P !member.dbref().name & ' [' & !member.type & ']'
enddo

    
重點：先印出目前元素與數量，再逐一處理。.members() 的回傳內容請以公司版本的 SCRM 為準；不確定時改用 Q MEMBERS 或 COLLECT 交叉驗證。

  


  

    
2. 依屬性值篩選並輸出 CSV唯讀＋寫檔


-- 示意：把符合條件的元件寫成 CSV
-- !list 由前面的 COLLECT 取得，例如：
-- var !list collect all VALV for CE

!f = object FILE('C:/temp/check.csv')
!f.open('WRITE')
!f.writeRecord('NAME,TYPE')

do !e values !list
    if (!e.type eq 'VALV') then
        !f.writeRecord(!e.dbref().name & ',' & !e.type)
    endif
enddo

!f.close()
$P 'Done: check.csv'

    
重點：欄位含逗號或引號時要先跳脫；開檔失敗要用 handle 接住。需要 owner 名稱時，先確認該版本支援的取法，不要假設每個元素都有同樣的方法。輸出位置建議放個人暫存區。

  


  

    
3. 有錯誤處理的檔案讀取錯誤處理


-- 示意：讀檔並逐行處理，檔尾用 .unset() 判斷
!path = 'C:/temp/input.txt'
!f = object FILE(!path)
!f.open('READ')
handle (160,9)
    !!alert.error('找不到檔案：' & !path)
    return
elsehandle (41,319)
    !!alert.error('沒有權限：' & !path)
    return
endhandle

do
    !line = !f.readRecord()
    break if (!line.unset())
    $P $!line
enddo
!f.close()

    
重點：handle 必須緊接在可能出錯的那一行之後；開放式 do 一定要有 break if。

  


  

    
4. 最小表單：輸入 → 查詢 → 回填PML2 表單


-- pipetool.pmlfrm
setup form !!pipetool size 44 12
    title '管線檢查工具'
    text .txtName '名稱:' at x1 y2 width 26 is STRING
    button .btnPick '讀取 CE' at x30 y2 callback '!this.pick()'
    button .btnClear '清除' at x30 y4 callback '!this.clear()'
exit

define method .pick()
    !this.txtName.val = !!ce.dbref().name
endmethod

define method .clear()
    !this.txtName.val = ''
endmethod

    
重點：檔名、setup form 的名稱與呼叫名稱要一致；新增檔案後執行 pml rehash all。關閉表單請用產品提供的關閉機制，不要自訂一個同名 method 造成遞迴。

  


  

    
5. 用 handle 包住整段批次工作部署


-- 示意：批次工具的外殼
define function !!mycoBatchRun(!zone is STRING) is BOOLEAN
    handle any
        $P 'FAILED: ' & !!error.text
        return FALSE
    endhandle

    $P 'Start: ' & !zone
    var !items collect all BRAN for CE
    !count = 0
    do !item values !items
        !count = !count + 1
        $P 'Item: ' & !item.dbref().name
    enddo
    $P 'Items: ' & !count
    return TRUE
endfunction

    
重點：批次工具要能「失敗但不中斷」，並留下可追查的訊息。!!error.text 的欄位名稱依版本確認；計數請自己維護，不要依賴陣列長度。

PRACTICE
練習題
只在訓練專案執行



  
1. 陣列暖身　建立含 5 個管線名稱的陣列，跳過索引 3 不設值，用 do ... values 印出。觀察間隙元素印出什麼。

  
2. 唯讀查詢　寫一個巨集，印出 !!CE 的名稱、型別、owner 名稱，以及同層所有 VALV 的數量。

  
3. 屬性核對　用 Q ATT 與 Q POS WRT 查同一個元素，把輸出貼進筆記，標出哪些是資料庫屬性、哪些是即時計算的偽屬性。

  
4. 表單小工具　做一個表單：一個輸入框、一個「讀取 CE」按鈕、一個「關閉」按鈕。按鈕按下後把 CE 名稱填進輸入框。

  
5. 錯誤處理　把練習 4 改成「讀取外部 CSV 並顯示前 5 行」，故意給錯路徑，確認 handle 能顯示訊息且巨集不中斷。

  
6. 除錯與部署　用 PML TRACE 或 $R 追蹤一支含迴圈的工具，找出執行最久的一行；再把工具包成 Add-in 或批次入口。
